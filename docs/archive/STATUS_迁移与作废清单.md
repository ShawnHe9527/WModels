## 二、保住的部分

### 2.1 NEURON 模型资产（逐字节来自官方）

⇒ **模型本身没错，从来没跑偏。** 错的只是我们自己写的"实验装置"。

### 2.2 代码基础设施

| 模块 | 为什么保留 |
|---|---|
| `core/safety.py` | 内存护栏 + 预检，与任务无关 |
| `core/progress.py` | 终端实时进度条（用户要求）|
| `learn/model.py` | Encoder/Predictor/Decoder 结构 + **残差输出**开关 |
| `eval/evaluate.py` | **配对评测**（模型与 L0 用同一批样本），是解决 n=32 噪声的关键 |
| `eval/baselines.py` | L0/L1/L2/L3 四种基线的实现 |
| `gen/secinfo.py` | NEURON 会话管理 + θ_s 提取（需改路径）|

### 2.3 方法论与技术结论（这些与数据无关，仍然成立）

| 结论 | 实测证据 | 为何仍然成立 |
|---|---|---|
| **残差输出消除系统性偏差** | 绝对解码误差恒为 1.6e-3（不随 $k$ 变）；增量误差只有真实增量的 8–15% | 这是**解码器**的性质，与任务无关：任何"编码→解码"都有平台偏差，相减即消 |
| **闭环尾损失治暴露偏差** | $k{=}50$ 误差 0.062 → 0.0084（**7.4×**）| 教师强制必然让 Predictor 没见过自己的漂移 latent，这是通用缺陷 |
| **latent 轨迹会发散** | 放大比从 2.6×($k{=}10$) 单调涨到 79.7×($k{=}500$) | Predictor 的 Jacobian 谱半径 > 1，与具体任务无关 |
| **评测必须配对且 $n\ge256$** | $n{=}32$ 时同一视界估出 0.050/0.110/0.067，真值 0.0673（±50%）| 纯统计问题 |
| **不能只用 √k·σ 当硬门禁** | 实测放大比 0.09–0.14，误差可相互抵消 | 理论适用性判断 |
| **要读实验脚本，不只读模型定义** | 本次最大的错 | 模型 = 形态 + 通道 + **实验装置** |

## 三、一句话总结

> **模型资产和代码骨架保住了；所有数据和所有"输/赢"的结论作废。**
>
> 这不是"白干"——我们搞清楚了：
> 1. 我们读错了模型（以为没突触，其实每段一对）；
> 2. 我们的输入方式错了（电压钳把 $V$ 钉死，而论文里 $V$ 是状态）；
> 3. 三个通用的技术手段（残差输出、闭环尾损失、配对评测）已被验证有效，
>    可以直接搬到新方案上。
