## 2. §前序脚本的实验设计缺陷（为何不复用）

| # | 缺陷 | 后果 |
|---|---|---|
| D1 | 协议总时长仅 **12.5 ms**（记录窗 7.5 ms） | 持久性基线 R²=0.998~1.0000 ⇒ **任务平凡**，R² 失效 |
| D2 | 用**裸 R²** 当验收指标 | 同上，指标无意义 |
| D3 | 突触输入按 **5 导频点池化** | 实测最差波形误差 **94.4%**（见 §4） |
| D4 | 记录窗**跨相位**（含 settle/cond/test） | 不同 horizon 落在不同相位 ⇒ skill 曲线不可比 |
| D5 | 突触输入**未归一化** | 电导跨 2~3 数量级 ⇒ 梯度病态 |
| D6 | 数据集全量 `torch.stack` 展开 | 467 MB × 2~3 ⇒ **OOM（exit 137）** |

⇒ 本轮的 `wm_sec.py` 逐条修正：相位单一只记 test 相、只用 horizon skill、
逐 compartment 输入、输入也归一化、npz mmap 懒加载。

### 3.2 顺藤摸瓜：手工转录的门控速率失真

它正好印证了用户的判断：**前序资产有缺陷，必须审计后再用**。

### 3.3 修复方案：从 NEURON **数值制表**

`world/stage1_sec/wm_gates.py`：

1. 发现 .mod 里 `minf/mtau` **不是 RANGE** ⇒ NEURON 不暴露 ⇒ 无法直接读
2. 改用**阶跃弛豫扫描**：用 `Vector.play` 把 V 波形灌进 SEClamp，
   **一次仿真**扫完 96 个电位，记录该段上**所有**门控
3. 利用 `SOLVE states METHOD cnexp` ⇒ m(t) 在数学上是**精确单指数**
   ⇒ 三参数拟合 (A, B, τ) 反解 g∞(V) 与 τ(V)
4. 运行时把 `L5PC_gates.gate_inf_tau` **和** `L5PC_unit_sec.gate_inf_tau`
   一起替换（后者是关键，见 §3.5）

**精度验证**（表 vs NEURON 稳态，直接对照）：

| V | 机制 | NEURON | 解析版 | **制表版** |
|---|---|---|---|---|
| 0 | NaTs2_t.m | 0.9755 | **0.16** ❌ | **0.9901** ✅ |
| 0 | Ca_HVA.m | 0.9727 | **0.362** ❌ | **0.9847** ✅ |
| +20 | SKv3_1.m | 0.1348 | **0.533** ❌ | 0.2421 🟡 |
| −40 | NaTs2_t.m | 0.2390 | — | 0.2471 ✅ |

⇒ 制表版把误差从 **数倍** 压到 **1–2%**（除 SKv3_1 在极端电位仍偏大有待改进）。

### 3.4 制表过程中踩的 4 个坑（都已修）

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| G1 | `SEClamp` 默认 `dur1 = 50 ms` | 50 ms 后钳位关闭 ⇒ ginf 全 ≈ 0 | 显式 `dur1 = 1e9` |
| G2 | 每电位 `finitialize()` | 190 次初始化 ⇒ 制表 >10 min/机制 | `Vector.play` 一次跑完 |
| G3 | V 按 1 mV 递增访问 | 相邻段弛豫幅度≈0 ⇒ 拟合病态 | **随机排列**访问顺序 |
| G4 | `T_SEG` 太短（100 ms） | τ 被低估 30× ⇒ g∞ 外推有偏 ⇒ **补丁后误差 37%→118%** | `T_SEG = 2000 ms`（≫ τ_max=900 ms） |

### 3.5 ⚠️ Python 导入陷阱（值得单独记）

```python
# L5PC_unit_sec.py 第 54 行：
from L5PC_gates import MECH, gate_inf_tau, nernst_eca, pas_current
```

⇒ `gate_inf_tau` 被**按名字绑定**进 `L5PC_unit_sec` 的命名空间。
   事后改 `L5PC_gates.gate_inf_tau = ...` **完全无效**
   （实测：补丁前后端口电流**逐位相同** ⇒ 说明根本没生效）。

**正解**：必须同时改 `L5PC_unit_sec.gate_inf_tau`。

## 4. 输入设计缺陷（用户质疑的正是这点）

### 实测：空间池化不可接受

`world/probes/probe_input_spatial.py`（同一时间波形，只变空间分布）：

| 输入表示 | 维度 | 中位误差 | **最差误差** |
|---|---|---|---|
| 逐 compartment 精确 | 2+2·nseg | **0.00%** | **0.00%** ✅ |
| **5 导频池化（旧版）** | 12 | 6.21% | **94.42%** 🔴 |
| 均匀标量 | 4 | 11.96% | 546% 🔴 |
| 总量+重心 | 6 | 99% | 648% 🔴 |

逐模式（P=5）：uniform 0.00% / single 5.57% / **end 94.42%** / alternate 6.85%

⇒ **同一总电导，位置不同 ⇒ 端口电流差最多 94%。**
   **空间分布本身就是"影响输出的因素"，不能被近似掉。**

### 修正

`d_u = 2 + 2·nseg`（我们模型 nseg 最大 13 ⇒ 最多 28 维，完全可承受）。
外加**输入 z-score 归一化**（含 log，应对 2~3 个数量级）。
